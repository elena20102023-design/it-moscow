# Валидация форм — IT.МОСКВА

Проект: «Стол заказов проектов» — обмен учебными книгами и материалами для студентов колледжа IT.МОСКВА.

## Структура директорий

- `front/index.html` — каталог, форма объявления, форма вопроса.
- `front/styles/main.css` — оформление полей, ошибок и подтверждения.
- `front/scripts/main.js` — проверка данных и локальное сохранение.
- `design/desktop.svg`, `design/mobile.svg` — макеты с обратной связью.
- `design/validation.svg` — состояния формы: исходное, ошибки, успех.
- `docs/validation.md` — правила и сценарии проверки.
- `analysis/` — аудитория и CJM.
- `UI-kit.html` в корне репозитория — UI-kit проекта.

## Правила

Все поля обязательны. Перед проверкой строк удаляются пробелы по краям. Длина считается по JavaScript `String.length`; пробелы внутри текста сохраняются.

| Форма | Поле | Допустимые значения |
|---|---|---|
| Объявление | Тип | Ищу материал / Предлагаю обмен |
| Объявление | Категория | Книги / Конспекты / Материалы |
| Объявление | Название | 1–80 символов |
| Объявление | Предмет | 1–55 символов |
| Объявление | Описание | 1–320 символов |
| Обратная связь | Имя | 2–50 символов |
| Обратная связь | Сообщение | 10–500 символов |

Пустое поле: «Заполни это поле». Слишком короткое: «Введи не менее N символов». Слишком длинное: «Не более N символов». Недопустимый пункт списка: «Выбери значение из списка».

## Поведение интерфейса

Проверка запускается при выходе из поля и отправке формы. Ошибка находится под полем и связана с ним через `aria-describedby`; `aria-invalid` сообщает состояние. После исправления ошибка исчезает при вводе. При неудачной отправке фокус переходит к первому неверному полю; данные не сохраняются и введённый текст остаётся.

После успешного создания объявление появляется в каталоге. Обратная связь очищается только после сохранения, затем выводится подтверждение. Если хранилище недоступно, сообщение остаётся в форме и предлагается повторить попытку.

## Хранение и ограничения MVP

Это учебный frontend без сервера. Объявления и отклики используют `it-moscow.exchange.v1`, вопросы — отдельный ключ `it-moscow.feedback.v1` в localStorage. Сообщения не отправляются администрации. Старые объявления и отклики сохраняются при обновлении. Текст карточек выводится через `textContent`.

Клиентская валидация улучшает интерфейс, но не заменяет серверную проверку. При подключении backend необходимо повторить правила на сервере, добавить аутентификацию, ограничение запросов и модерацию.

## Сценарии приёмки

1. Отправить пустые формы: ошибки у всех пустых полей, фокус у первого, новых записей нет.
2. Ввести только пробелы: ошибка обязательности.
3. Имя из 1 символа и сообщение из 9: ошибки минимальной длины.
4. Имя из 2 и 50 символов, сообщение из 10 и 500: допустимы; сверх максимума — ошибка (при программном изменении, обычный ввод ограничен maxlength).
5. Исправить ошибку: подсказка исчезает без повторной отправки.
6. Сохранить валидный вопрос: подтверждение, очистка формы, запись в localStorage.
7. Запретить localStorage: текст обратной связи не теряется, показана ошибка сохранения.
8. Опубликовать объявление, обновить страницу: оно остаётся; поиск, фильтры, отклики и закрытие объявления продолжают работать.
9. Проверить с клавиатуры и на узком экране: все поля и кнопки доступны, горизонтальной прокрутки нет.

## Проведённая проверка

В Edge проверены пустая форма вопроса, короткие имя и сообщение, исправление ошибок и успешное локальное сохранение с очисткой полей. В форме объявления проверены ошибки пустых полей и фокус. Отдельно проверены границы длины 2/50 для имени и 10/500 для сообщения, превышение границ и допустимые значения типа. JavaScript прошёл синтаксическую проверку. ## Регистрация

Кнопка «Регистрация» в шапке открывает диалог. После сохранения она меняется на «Мой профиль». В диалоге доступны данные демопрофиля и кнопка создания другого демопрофиля. Каталог доступен без регистрации.

| Поле | Правило |
|---|---|
| Имя | Обязательное, 2–50 символов после удаления крайних пробелов |
| Email | Обязательное, до 254 символов; непустые части до и после @, точка в домене, без пробелов |
| Учебная группа | Обязательная, 2–20 символов после удаления крайних пробелов; пример ИСП-21 |
| Пароль | Обязательный, 8–128 символов, хотя бы одна буква и цифра; пробелы не удаляются |
| Повтор пароля | Обязательный, точное совпадение с паролем |

Проверка при выходе из поля и отправке. При исправлении ошибки сообщение обновляется на вводе. Изменение пароля повторно проверяет уже проверенное подтверждение. Ошибка препятствует сохранению, фокус у первого неверного поля. Успех показывается внутри диалога, имя/email/группа выводятся текстом. При ошибке localStorage остаётся форма с сообщением о неудаче.

В `it-moscow.profile.v1` сохраняются только имя, email, группа и время создания; пароли и подтверждение не сохраняются и никуда не отправляются. При успехе и закрытии диалога пароль очищается. При обновлении страницы демопрофиль восстанавливается. Это демонстрация регистрации для учебного frontend, а не серверная аутентификация, проверка принадлежности к колледжу или подтверждение email.

Макет `design/registration.svg`: исходная форма, ошибки полей и успешное сохранение. Для реальной регистрации необходим backend с серверной валидацией, безопасным хешированием паролей, сессиями и проверкой email.

### Приёмка регистрации

1. Пустая форма — ошибки обязательности у всех полей, фокус у имени.
2. Пробельные имя и группа — ошибка; имя в 1 символ и группа в 1 символ — ошибка длины.
3. `student@`, `student example.com`, `student@example` — ошибка email; `student@example.com` — допустим.
4. Короткий пароль, только буквы или только цифры — ошибка; пароль `Demo1234` — допустим.
5. Несовпадающее подтверждение — ошибка; изменение исходного пароля обновляет состояние подтверждения.
6. Имя из 2/50 символов, группа из 2/20, пароль из 8/128 — допустимые границы, превышения отклоняются.
7. Валидная форма — успешная регистрация, очищенные пароли, кнопка «Мой профиль», профиль сохраняется после обновления.
8. Закрыть диалог до успеха — значения паролей очищены.
9. При недоступном хранилище нет ложного успеха и можно повторить попытку.

Проверено для регистрации: в Edge — пустая форма и фокус на имени, короткие имя/группа, неверный email, пароль без цифры, несовпадение подтверждения, исправление и успешное создание профиля, восстановление профиля после обновления. Отдельные проверки JavaScript подтвердили границы длины, email, состав пароля и подтверждение. Синтаксическая проверка пройдена. Ошибки хранилища и мобильный экран перечислены как сценарии приёмки, отдельно в этой итерации не проверялись.
